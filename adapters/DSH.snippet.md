# Optional DSH / host-specific standing guidance

When a task has several independently verifiable subproblems, first evaluate `kha-orchestrator` as an optional KHA CLI cloud delegation workflow. Use it only when it beats DSH's local or native subagent tools on expected quality or critical path, with explicit cost/data/tool authority. Do not mix DSH native delegation and KHA multi-session workflows by default. Keep final verification and delivery with the current DSH agent. For DSH variants, check their actual project/standing-instructions configuration before merging; invoking /kha-orchestrator by name is a portable fallback.
